Context

Project 1: Classic Game was the first major project in EECS 494: Game Development and Design. The task was to re-implement the first region of Metroid (Nintendo, 1986) in Unity, and design a short custom level around a new mechanic, working through three deliverables with aggressive deadlines: a Milestone, an Alpha, and a Gold.

Timeline

  • Week 1: Milestone - First Iteration / Prototype Classic Level. Played the original game to develop design intuition, set up Unity and git, and implemented basic functionality for each task.
  • Week 2: Alpha - Feature-Complete Classic Level. Cleaned up the code to cut script bloat, and completed functionality for all mechanics and levels.
  • Week 3: Gold - Final Deliverable Classic Level and Custom Level. Completed debugging and polishing all features, and implemented the Custom Level.

Team

I worked in a team of two. The task breakdown for the Milestone and Alpha had been provided, so our planning and discussions for those deliverables focused on splitting tasks between us, tracking priority and time estimates in Jira, and triaging when we fell behind. For the Gold deliverable, we brainstormed our mechanic and level design, created tasks and a roadmap before following the same process as the previous deliverables. We almost always worked in proximity, so as to keep us both familiar with the whole game and code base, and to allow us to help each other and maintain shared ownership.

Custom Level Design

The Original Pitch:
Welcome Samus's newest power-up: the Transformer Tool!
With this collectible, Samus can turn her enemies into harmless blocks and those blocks back into enemies. She wields the power to reshape her surroundings to her advantage or... disadvantage.

  • Choosing the Mechanic: My goal was to create a mechanic that provided interesting decision making oppurtunities. My partner and I brainstormed through a few ideas, including mazes with breakable walls, an invisible morph ball power-up, and a bubble mechanic, before deciding on a transformation weapon, the Transformer Tool. It was feasible to build in the time we had and fit Metroid well. A big part of the original game is killing aliens to survive, but the Transformer Tool allowed us to create situations where killing everything wouldn't always be the best move.
  • Teach the Mechanic through Level Design: The challenge was to teach the player how to use the Transformer Tool, without any text guidance. To acheive this, we set up our custom level with 2 rooms. In Room 1 the player starts trapped, so that they have to learn to use the Transformer Tool to transform walls into enemies in order to escape and progress. In Room 2, we created a level that was impossible to pass by just killing or running past enemies, so as to teach the player to transform enemies back into walls in order to progress.
